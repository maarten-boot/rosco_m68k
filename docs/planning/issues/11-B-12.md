# InterfaceReference.md does not match TRAP 13 / TRAP 15 behaviour

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** Confirmed by reading and in the R-3 conformance table.
**Review IDs:** B-12, B-20, E-9

## Description
- **B-12** SPI_INIT is documented as "0 = OK", but it returns 1 (true) on success (and SPI_ASSERT_CS/DEASSERT_CS use "0 = failed").
- **B-20** CHECK_SD / CHECK_SPI / CHECK_ATA_SUPPORT (FC 0, 5, 15) also trash A0, like every TRAP 13 function, but only D0 is listed.
- **E-9** TRAP 15 task 9 halts directly and never uses EFP_HALT.
Doc-only fix proposed so existing callers keep working (also updates the task 7/8 text for the E-5/E-4 fixes).
