# SD block write ignores the data-response token: rejected writes are reported as success

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** Confirmed in MAME: injecting a write-error token ($0D) still returned success before the fix; normal writes verified by read-back.
**Review IDs:** B-5

## Description
After the data block, the code only waits for MISO to return to $FF. A rejected block (CRC/write-error token) has no busy phase, so the next byte is $FF and the write "succeeds". `WRITE_RESPONSE_OK` is defined in bbsd.h but unused. This matters for anything writing through TRAP 13 (e.g. an OS using the ROM SD driver).

## Where (develop @ ec229f9)
- `code/firmware/rosco_m68k_firmware/stage1/blockdev/bbsd.c:281 (BBSD_write_block)`

## How to reproduce
`tests/t_sdw.asm` (TRAP 13 init/write/read-back) and `mame/sdw_bad.dbg` (token injection).

## Proposed fix
Read the token, require `(token & 0x1F) == 0x05`, then wait for the busy phase to end.
Branch: `fix/B-5` on maarten-boot/rosco_m68k
