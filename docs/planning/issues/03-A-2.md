# `__divsi3`/`__modsi3` in the firmware are unsigned, so signed division is wrong

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** Confirmed in MAME by calling the ROM helpers: −7/2 = $7FFFFFFC, −7%2 = 1, 7/−2 = 0.
**Review IDs:** A-2, B-14

## Description
On 68000/68010 GCC calls the libgcc helpers for `int` `/` and `%`. The firmware provides its own `__divsi3`/`__modsi3`, but they take `uint32_t` and call the unsigned `divmod`, so any negative operand gives a wrong result (no current firmware path is known to divide negative numbers, so this is latent but a trap for future code).

## Where (develop @ ec229f9)
- `code/firmware/rosco_m68k_firmware/stage1/common.c:29`

## How to reproduce
`tests/t_div_m.asm` (adjust DIVSI3/MODSI3 to the addresses in the build's map).

## Proposed fix
Compute magnitudes unsigned and apply C sign rules (truncate toward zero, remainder follows the dividend); see branch.
Branch: `fix/A-2-B-14` on maarten-boot/rosco_m68k
