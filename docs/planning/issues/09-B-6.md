# SD timeouts are poll counts, far shorter than the SD spec on the bit-banged SPI

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** Confirmed in MAME: a card held busy is abandoned after the old poll count; with the fix, after ~540 ms (time-based). Slow real cards not tested.
**Review IDs:** B-6

## Description
E.g. 2500 polls for write busy vs. up to 250 ms (500 ms SDXC), 200 polls for read access vs. 100 ms, 400 ACMD41 tries vs. 1 s. Slow cards then fail writes/init.

## Where (develop @ ec229f9)
- `code/firmware/rosco_m68k_firmware/stage1/blockdev/include/bbsd.h:55 (and the other *_RETRIES/*_TIMEOUT)`

## How to reproduce
`tests/t_sdw_t.asm` + `mame/sdt_busy.dbg` (forces the card busy forever and measures ticks).

## Proposed fix
Measure waits with SDB_UPTICKS (read 200 ms, write/busy 500 ms, init 1 s) with large poll caps as fallback when interrupts are masked; forced reset/idle commands keep the short wait so a no-card boot is not slowed (checked: same boot time). Based on fix/B-5.
