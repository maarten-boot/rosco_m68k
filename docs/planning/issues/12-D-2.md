# libs cstdlib: memcpy returns the wrong pointer, memmove/memcmp missing, strtol whitespace/endptr

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** D-2 and D-4 (whitespace) confirmed in MAME; D-3 by link inspection.
**Review IDs:** D-2, D-3, D-4

## Description
- **D-2** `memcpy` returns `dest + n` instead of `dest`; `strncpy` returns memcpy's result and inherits it.
- **D-3** no `memmove`/`memcmp`, which GCC may emit for struct copies/compares even with `-ffreestanding` → link errors.
- **D-4** `strtol` skips only `' '` (so `"\t42"` → 0, also via atoi/atol); with no digits, `*endptr` must equal `nptr`.
