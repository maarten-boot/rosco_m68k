# SD init reports success when CMD58 (read OCR) fails, leaving the card struct uninitialised

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** Confirmed in MAME with fault injection (forcing the CMD58 result non-zero).
**Review IDs:** B-4

## Description
In `BBSD_initialize`, the V2 path does `if (raw_sd_command(58, 0)) goto finally;` while `result` is still `BBSD_INIT_OK`. `sd->initialized`/`sd->type` are never set, but callers (stage2, TRAP 13 SD_INIT users) are told the card is usable.

## Where (develop @ ec229f9)
- `code/firmware/rosco_m68k_firmware/stage1/blockdev/bbsd.c:68`

## How to reproduce
`mame/b4_cmd58_inject.dbg` (set the address of the `tst.b d0` after CMD58 from the build's disassembly).

## Proposed fix
Return a new status `BBSD_INIT_CMD58_FAILED` (`SD_INIT_CMD58_FAILED` in sdfat.h, ordinal 4).
Branch: `fix/B-4` on maarten-boot/rosco_m68k
