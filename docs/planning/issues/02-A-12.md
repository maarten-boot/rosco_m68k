# Serial PRINT/PRINTLN (TRAP 14 fn 0/1) clobber D0 although documented to modify only A0

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** Confirmed in MAME on v2.42 and on develop ($DEADBEEF comes back as $DEADBE00).
**Review IDs:** A-12

## Description
The default DUART console uses D0 as its character register and only saves A1. InterfaceReference.md says PRINT/PRINTLN modify only A0. The V9958 and Xosera consoles already comply.

## Where (develop @ ec229f9)
- `code/firmware/rosco_m68k_firmware/stage1/duart.asm:214 (EARLY_PRINT_DUART)`

## How to reproduce
`tests/t_easy_m.asm` (first line of output: `#A12 D0 after PRINT=`).

## Proposed fix
Save/restore D0 with A1 (`movem.l D0/A1,-(A7)` … `movem.l (A7)+,D0/A1`).
