# libs: libm.a contains every library's objects (incl. the float printf)

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** Confirmed: `m68k-elf-ar t libm.a` listed 313 members incl. printf.o, sdfat, vterm, heap, sst_flash, kinit.
**Review IDs:** D-7

## Description
`SOURCES=$(shell find . -name "*.c")` runs from `libs/`, not from the libm directory. Programs linking `-lm` can silently pick up the float `printf_` from libm.a instead of libprintf/libprintf-softfloat. (Related, not changed: `$(filter-out **/printf-*.o, …)` in libs/Makefile is a no-op because filter-out uses `%`; fixing it would drop printf from librosco_m68k.a, so that needs a maintainer decision.)

## Where (develop @ ec229f9)
- `code/software/libs/src/libm/include.mk:1`

## How to reproduce
`m68k-elf-ar t src/libm/libm.a`.

## Proposed fix
Search only the libm directory (288 math objects); all example programs still build.
