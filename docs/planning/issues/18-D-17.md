# libs sst_flash: toggle-bit wait has no timeout (updateflash can hang with interrupts masked)

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** Timeout path tested in MAME with RAM standing in for the flash and DQ6 forced to toggle; real flashing untested (MAME maps the ROM read-only).
**Review IDs:** D-17

## Description
`wait()` polls DQ6 until it stops toggling with no limit, so a missing/protected/failing chip hangs updateflash forever. Proposed fix is deliberately minimal (no verify step, no extra interrupt masking) because it cannot be tested without flash emulation.

## Where (develop @ ec229f9)
- `code/software/libs/src/sst_flash/sst.c:31`

## How to reproduce
`tests/sst_timeout_test.c` + `mame/sst_stuck.dbg`.

## Proposed fix
Bound the wait (1,000,000 polls ≈ 5 s at 10 MHz) and return false; updateflash already checks the result.
