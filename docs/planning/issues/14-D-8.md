# libs printf: %e/%g/%lld disabled but arguments then misalign; %f > 1e9 restarts sprintf output

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** Confirmed in MAME: `"%lld|%d"` → `"|0"`, `"%e|%d"` → `"e|1073217536"`, `sprintf(b,"ab%fcd",1e10)` → n=2, b="cd".
**Review IDs:** D-8

## Description
With exponential and long-long support disabled, `%e/%g` are skipped without consuming their argument and `%lld` consumes only a `long`, so every following argument is wrong. For |value| > PRINTF_MAX_FLOAT, `_ftoa` returns 0 – the output *index* – so sprintf restarts at the beginning of the buffer. Enabling exponential output also exposes two upstream `_etoa` issues: 0.0 prints as `0.000000e-308`, and 1e10 as `10.000000e+09`.

## Where (develop @ ec229f9)
- `code/software/libs/src/printf/include/printf_config.h:19`
- `code/software/libs/src/printf/printf.c:362`

## How to reproduce
`tests/libtest/` (D-8 lines).

## Proposed fix
Enable both features (+3 KiB softfloat, +1 KiB nofloat), return `idx`, special-case zero and renormalise after rounding in `_etoa`.
