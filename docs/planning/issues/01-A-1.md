# TRAP 14 DEVICE_CTRL ignores the parameter in D2 and always writes $40 to the DUART CSR

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** Confirmed in MAME (watchpoint on CSRA: requested $BB, written $40; console stops afterwards).
**Review IDs:** A-1

## Description
InterfaceReference.md (DEVICE_CTRL, function 16), the handler's own header comment and the libs' `mcDeviceCtrl` all pass the command parameter in **D2.L**, but `D_CTRL_DUART_A/B` write **D1** to CSRA/CSRB. At that point D1 is no longer the caller's value: the TRAP 14 dispatcher has already turned the function code into `16*4 = 64`, so every "set baud rate" request writes `$40` to the clock-select register.

## Where (develop @ ec229f9)
- `code/firmware/rosco_m68k_firmware/stage1/duart.asm:404`
- `code/firmware/rosco_m68k_firmware/stage1/duart.asm (D_CTRL_DUART_B, CSRB)`
- `code/firmware/rosco_m68k_firmware/stage1/trap14.asm (dispatcher multiplies D1 by 4)`

## How to reproduce
`tests/t_a1.asm`: GET_DEVICE 0, then TRAP 14 fn 16 with D0=0, D2=$BB; watch writes to CSRA ($F00003) with `mame/run_api.dbg`-style watchpoint.

## Proposed fix
`move.b D2,DUART_CSRA(A0)` / `move.b D2,DUART_CSRB(A0)` (and fix the comment).
