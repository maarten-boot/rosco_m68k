# ATA: LBA28 only (addresses ≥ 2^28 silently wrap) and writes are not completed/checked

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** B-8 confirmed in MAME on a v2.42 build with the ATA EFPs enabled (partition at LBA 2^28+2048 read the decoy at LBA 2048). B-9 by reading. No fix branch yet.
**Review IDs:** B-8, B-9

## Description
- **B-8** LBA bits above 27 are dropped; only READ/WRITE PIO (0x20/0x30) are used, IDENTIFY capacity is not consulted. On disks > 128 GiB a partition beyond the limit reads – and **writes** – the wrong sectors.
- **B-9** `ata_write_one` does not wait for BSY to clear, check ERR/DF, or issue CACHE FLUSH; write errors are reported as success.

## Where (develop @ ec229f9)
- `code/firmware/rosco_m68k_firmware/stage1/blockdev/ata.c:216 (read)`
- `code/firmware/rosco_m68k_firmware/stage1/blockdev/ata.c:250 (write)`

## How to reproduce
Sparse ~129 GiB raw `.hd` image as `-hard2` with a FAT32 partition at LBA 2^28+2048 and a different FAT32 volume at LBA 2048 (recipe in tests/README.md).

## Proposed fix
Interim: reject LBA ≥ 2^28. Proper: READ/WRITE SECTORS EXT using IDENTIFY words 83/100-103; poll status after writes and FLUSH CACHE.
