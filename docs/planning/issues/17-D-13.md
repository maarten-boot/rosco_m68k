# libs gdb stub: ring-buffer mask never set; DUART status read from absolute addresses

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** By reading; not runtime-tested (no m68k gdb available). Fixes compile.
**Review IDs:** D-13, D-14

## Description
- **D-13** `uart_b.mask` stays 0 (bss), so `duart_buffer_char` always writes `data[0]`: input received while the target runs is lost.
- **D-14** `move.b DUART_SRA,D0` reads absolute address $2 (a reset-vector byte) instead of `DUART_SRA(A0)`; same for SRB. Also noted, not changed: the shared `.error` path resets UART A's overrun even for UART B.

## Where (develop @ ec229f9)
- `code/software/libs/src/gdb/gdb-support.c:51`
- `code/software/libs/src/gdb/interrupt.asm:125 (and the SRB read)`

## How to reproduce
—

## Proposed fix
Set `mask = sizeof(data) - 1`; use `(A0)`-relative reads.
Branch: `fix/D-13, fix/D-14` on maarten-boot/rosco_m68k
