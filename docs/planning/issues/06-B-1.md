# stage2 loaders do not bound kernel loads: oversized ROSCODE1.BIN causes a crash/reboot loop

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** B-1 confirmed in MAME (768000-byte BIN → bus error at PC=$0F0206 → warm boot reloads the file → endless loop). B-2/B-3 by reading.
**Review IDs:** B-1, B-2, B-3

## Description
- **B-1** `load_kernel_bin` reads blocks to the load address with no upper limit. Anything past ~704 KiB overwrites the running stage2 (and stack/SDB). Because the crash warm-boots and the card is still inserted, the board loops until the card is removed. The ELF path already has `load_range_allowed()`.
- **B-2** Kermit `writefile()` memcpy's every data packet with no limit either.
- **B-3** The ELF loader range-checks `p_memsz` but reads `p_filesz` bytes; with `p_filesz > p_memsz` it writes past the checked range and `memset(…, p_memsz - p_filesz)` underflows.

## Where (develop @ ec229f9)
- `code/firmware/rosco_m68k_firmware/stage2/load/load.c:66 (load_kernel_bin)`
- `code/firmware/rosco_m68k_firmware/stage2/load/load.c:155 (ELF segment check)`
- `code/firmware/rosco_m68k_firmware/stage2/kermit/kermit_support.c:92 (writefile)`

## How to reproduce
FAT32 SD image (MBR, partition at LBA 2048) with a 768000-byte ROSCODE1.BIN; boot in MAME with `-hard1`.

## Proposed fix
Check each BIN block with `load_range_allowed()`; refuse Kermit packets that would cross STAGE2_LOAD; reject `p_filesz > p_memsz`.
