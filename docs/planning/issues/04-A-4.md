# Two stage1 assembler slips: `or.w #0700,SR` (decimal) and word-sized decompress return

**Affects:** release v2.42 and `develop` @ ec229f9 (r2.x, default build)
**Found by:** code review of v2.42 plus runtime tests in MAME (`rosco_m68k_010`); details in docs/planning/tests/ (branch `planning/session-docs` on maarten-boot/rosco_m68k)
**Status:** A-4 confirmed in the assembled ROM (`oriw #$02BC,%sr`). A-9 confirmed by reading; latent with the current stage2 size.
**Review IDs:** A-4, A-9

## Description
- **A-4:** the bus-error/address-error/illegal-instruction LED handlers use `or.w #0700,SR`. vasm reads `0700` as decimal 700 = `$02BC`, which does not mask interrupts to level 7 (and sets stray CCR bits). Everywhere else uses `$0700`.
- **A-9:** `decompress_stage2` returns `move D2,D0` (word). The upper word of D0 still holds the input length, so a failed decode of a compressed stage2 ≥ 64 KiB would look like success to `main1.c`.

## Where (develop @ ec229f9)
- `code/firmware/rosco_m68k_firmware/stage1/rev2.asm:107 (and two more in rev2.asm, three in rev1.asm)`
- `code/firmware/rosco_m68k_firmware/stage1/decompress.asm:10`

## How to reproduce
A-4: `objdump -d` of the ROM around the handlers. A-9: flip a byte in the zipped stage2 (still detected today because the image is < 64 KiB).

## Proposed fix
`#$0700`; `move.l D2,D0`.
Branch: `fix/A-4 and fix/A-9` on maarten-boot/rosco_m68k
